# final2: per-commit effect, measured on one machine

Setup:
- One `bb` per commit: `bb15fcb` + harness (0001-0002) + commits 0003..k. `00-baseline` is `bb15fcb` + harness.
- 74 binaries round-robin, binary order shuffled per flow and rep, 5 reps, on a quiet 4 vCPU Xeon @ 2.80 GHz without IFMA.
- Flows: `standards_token_transfer_private_to_private` (headline), `ecdsar1+transfer_1_recursions+private_fpc`,
  `ecdsar1+storage_proof_7_layers+sponsored_fpc`, `ecdsar1+amm_add_liquidity_1_recursions+sponsored_fpc`,
  `schnorr+deploy_schnorr+sponsored_fpc` (5 flows, 1850 runs, 0 failures). Raw data: `per_commit_bench_runs.csv`.
- "wall vs prev": median over reps of (sum over flows of wall, binary k minus binary k-1) / baseline sum. The 90% CI is a
  bootstrap over reps. "cumulative wall" is median(sum_k)/median(sum_baseline).
- Peak RSS: per flow, max `getrusage` RSS over reps, summed over the 5 flows.
- Commits marked IFMA, `perf(wasm)` and test commits do nothing on this machine; their rows show the noise floor
  (about ±2% per commit). Single-commit effects under ~2% are not resolved by this run. See `per_patch_reported.md` for the
  numbers each author measured in isolation.
- Generated by `scripts/per_commit_report.py per_commit_bench_runs.csv --subjects <subjects.tsv>`.

Reps used: 5; flows: 5; baseline wall 55.28 s, cpu 153.31 s, peak RSS sum 2154 MiB
